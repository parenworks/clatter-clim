#+TITLE: clatter-clim roadmap
#+OPTIONS: toc:nil num:nil

Ordered so that the riskiest, most architecture-defining work is proven first.

* Phase 0: it loads and connects (native)

- [X] =(asdf:load-system :clatter-clim)= compiles clean against McCLIM and clatter-irc.
- [X] =(clatter-clim:run)= opens the frame on CLX with all panes laid out.
- [X] =Connect= then =Join #commonlisp= shows the channel buffer.
- [X] Inbound PRIVMSG renders in the messages pane.

This phase proves the bridge end to end.  Get it right before anything else.

* Phase 1: the bridge, deliberately stress-tested

- [ ] Confirm no pane is ever mutated off the frame thread (the only writer
      from the IRC thread is the locked mailbox in bridge.lisp).
- [ ] Flood test: join a busy channel, confirm no redisplay corruption and no
      lost or reordered lines.
- [ ] Batch drain: many messages arriving between frames coalesce into one
      repaint (already the design; verify under load).

* Phase 2: interaction polish

- [X] Click a nick to whois (:select) and to open a query (:describe): verify
      translators fire on CLX.
- [ ] Click a channel name in a message to join it.
- [X] Buffer list switches the current conversation on click.
- [X] Type-to-say: bare text in the interactor sends to the current buffer
      instead of requiring the =Say= command name.
- [X] NAMES / nick-list population on join (handle the relevant numerics via
      on-numeric, feeding :names updates).
- [X] Connect and Disconnect toolbar buttons (push-button gadgets).
- [X] SASL identify at connect time, and a Msg command for NickServ/ChanServ.
- [X] TAB nick completion on the last word, common prefix on ambiguity.
- [X] Per-nick colouring and self-mention highlight.

* Phase 2b: config panel and config file

- [X] A connect/config dialog using =accepting-values=: fields for server,
      port, nick, SASL password, and autojoin channels, with OK/Cancel.  It
      pre-fills from the config file and saves back to it on OK.  Confirmed on
      CLX; charmed-mcclim and clim-clog still to verify.
- [X] A persisted config file at ~/.config/clatter-clim/config.lisp: server,
      port, nick, autojoin, SASL password.  Read at boot to seed the defaults;
      written user-readable only (chmod 600).  The connect dialog saves to it.
- [X] Autojoin: on a successful connect, join the configured channels.

* Phase 2c: UI modernization (custom presentation-drawn controls)

- [X] Dark theme across all panes and dialogs, with no white flash on any
      backend (explicit fore/background inks on every pane).
- [X] Recolour McCLIM's built-in 3D gadget chrome by overriding the
      =*3d-*-color*= specials at boot, so default widgets stop looking grey.
- [X] Custom presentation-drawn toolbar buttons (Connect, Disconnect,
      Configure): rounded, padded, with a blue hover via a
      =highlight-presentation= method and a =ui-button= translator.
- [X] Reuse the same =ui-button= control for the config dialog's OK/Cancel
      (the dialog inherits the main command table so the translator applies).
- [X] Replace the config dialog's =accepting-values= popup with a themed
      custom frame, including an editable Port text field.
- [X] Custom flat scrollbars: a =handle-repaint= on =scroll-bar-pane= draws a
      subtle trough and a thin rounded thumb (12px), brighter while dragging,
      with no arrow buttons.
- [ ] RETURN TO: mask the SASL password field so it shows bullets instead of
      plaintext.  McCLIM's =text-field= is a Drei editor with no echo-char, so
      this needs either a custom Drei view that draws bullets while keeping the
      real buffer value, or folding the password into the custom text-entry
      field work below.
- [ ] Custom presentation-drawn text-entry fields with our own cursor and
      keystroke handling (replaces the Drei =text-field= gadgets), at which
      point masking is trivial.

* Phase 3: portability, the showcase

- [ ] Load =:mcclim-charmed=, run the identical frame with
      =(clatter-clim:run-terminal)=.  Confirm panes, presentations and command
      prompting work in the terminal.
- [ ] clim-clog entry point.  clim-clog today boots its own demo frame from a
      CLOG on-new-window function (clim-clog::start-frame).  To run an
      arbitrary frame class we need a small generic entry on the clim-clog
      side, for example =clim-clog:run-frame= that takes a frame class and a
      port, wiring the CLOG boot to find-port =(:clog ...)= and
      make-application-frame.  =run-web= is written against that seam.
- [ ] Demonstrate the same client running native, in a terminal and in a
      browser from one image.

* Phase 4: a real daily driver

- [ ] IRCv3 niceties clatter-irc already provides: SASL on connect,
      server-time on lines, message batches.
- [ ] Multiple servers / connections, one buffer list.
- [ ] DCC chat and send surfaced as commands and presentations.
- [ ] Persisted config (servers, autojoin) and logging via clatter-irc's
      *log-function*.
- [ ] Nick coloring, highlight on own nick, activity markers in the buffer list.
